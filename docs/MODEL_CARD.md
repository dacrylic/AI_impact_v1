# CPU Champion Model Card

## Purpose

This model is a CPU-first student that approximates a set of validated LLM
labels. It predicts the canonical classes `E0`, `E3`, and `E12`, where `E12`
combines the original teacher labels `E1` and `E2`.

It is a distillation model, not an independently validated measure of true AI
impact. The originating LLM rubric and prompt are not available in this
repository.

## Inputs And Exclusions

Required input:

- `keytask_content`

Optional input used by the champion:

- `jobrole_title`

Excluded from all model features:

- `jobrole_id`, task IDs, and other identifiers
- occupation and sector titles or codes
- `ai_impact_score`, categories, and source labels

The source `openai_label` is used only as a supervised training target. The
source distinction between `E1` and `E2` is used only as an auxiliary target
during training; the deployed target remains `E12`.

## Method

The champion, implemented in
[`run_cpu_aux_retrieval_oof_cv.py`](../src/ai_impact_classifier/experiments/run_cpu_aux_retrieval_oof_cv.py), combines CPU-only sparse features:

1. Four canonical word/character TF-IDF `LinearSVC` classifiers across
   task-only and title-plus-task views.
2. Two auxiliary four-class `LinearSVC` classifiers trained on the original
   `E0/E1/E2/E3` teacher labels.
3. Title-plus-task TF-IDF retrieval features: maximum and average similarity
   to known E3 examples, plus class-centroid similarities.
4. Two E3-versus-rest sparse SVM specialist scores.
5. A regularized multinomial logistic-regression meta-model.

All meta-features are cross-fitted. The meta-model does not see a base-model
score for a role generated by a base model trained on that role.

## Evaluation

Evaluation uses nested five-fold `StratifiedGroupKFold`, grouping on
`jobrole_id`. Each outer evaluation fold contains roles absent from all
corresponding training and inner-selection folds. Hyperparameters and class
biases are selected inside each outer development partition.

Aggregate out-of-fold results across 36,904 rows:

| Metric | Value |
| --- | ---: |
| Accuracy | 0.9085 |
| Macro F1 | 0.7803 |
| Weighted F1 | 0.9090 |

| Class | Precision | Recall | F1 | Support |
| --- | ---: | ---: | ---: | ---: |
| E0 | 0.9444 | 0.9361 | 0.9402 | 28,009 |
| E3 | 0.5879 | 0.5821 | 0.5850 | 201 |
| E12 | 0.8045 | 0.8275 | 0.8158 | 8,694 |

Fold macro F1 values were 0.7532, 0.7907, 0.8125, 0.7840, and 0.7266. The
variation means 0.7803 should be treated as an estimate, not a guaranteed
service-level result.

## Limitations

- E3 is rare and is the limiting class.
- The LLM label rubric is unavailable, so the student cannot be interpreted
  as a direct estimate of real-world AI impact independent of the teacher.
- Repeated identical task text can receive different labels across different
  job roles. This is compatible with role-conditioned labeling, but it limits
  what task text alone can recover.
- The champion is more complex than the simpler sparse baseline for a modest
  gain. The simple baseline scored 0.7711 macro F1 under the same outer-CV
  protocol.

## Intended Use

Use the model for batch triage or as a CPU-only proxy for the validated LLM
labels. Do not use it as the sole basis for high-stakes employment or policy
decisions without a separately documented rubric and human review process.
